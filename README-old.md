# Mini NPU 시뮬레이터 (Mini NPU Simulator)

AI 가속기(NPU)의 핵심 연산인 **MAC(Multiply-Accumulate, 곱누적)** 연산을 외부 수치 연산 라이브러리(NumPy 등) 없이 순수 파이썬으로 구현하고, 이를 통해 3x3 ~ 25x25 크기의 입력 패턴이 **Cross(+)**인지 **X** 모양인지 판별하는 경량 시뮬레이터입니다.

---

## 1. 실행 방법

### 환경 및 준비 사항
* **실행 환경:** Python 3.8 이상 (표준 라이브러리만 사용하므로 별도 `pip install` 불필요)
* **파일 위치:** `engine.py`, `main.py`, `data.json`이 모두 **동일한 루트 디렉토리**에 위치해야 합니다.

### 실행 및 모드 선택
터미널에서 아래 명령어로 진입점을 실행합니다.

```bash
python main.py
```

* **`1` 입력 (모드 1: 대화형 직접 입력)**
  * 콘솔에서 3x3 크기의 필터 A, 필터 B, 패턴 행렬을 한 행씩(숫자 3개, 공백 구분) 직접 입력합니다.
  * 입력 즉시 두 필터에 대한 MAC 점수, 승자 판정 결과, 그리고 3x3 연산 벤치마크 시간이 출력됩니다.
* **`2` 입력 (모드 2: data.json 일괄 채점)**
  * 루트 경로의 `data.json`을 자동으로 읽어 5x5, 13x13, 25x25 크기의 패턴들을 일괄 검증 및 채점합니다.
  * 전체 테스트 결과 요약(PASS/FAIL)과 크기별 성능 분석 표가 출력됩니다.

## 2. 구현 요약

### 1) 라벨 정규화 방식 (`normalize_label`)
* **목적:** 데이터셋마다 다를 수 있는 표기법(`+`, `cross`, `x`, `X`)의 불일치를 해소합니다.
* **동작 원리:**
  * 입력 문자열의 앞뒤 공백을 제거하고 소문자로 변환(`strip().lower()`)합니다.
  * `"+"` 또는 `"cross"` -> **`"Cross"`**로 통일
  * `"x"` -> **`"X"`**로 통일
  * 그 외 정의되지 않은 라벨은 `ValueError`를 발생시켜 결함 데이터로 안전하게 격리합니다.

### 2) 순수 MAC 연산 구현 개요 (`mac`)
* **원리:** 하드웨어 MAC 유닛의 동작을 모사하여 두 N x N 행렬의 동일 좌표 원소를 순차적으로 곱하고 누적 합산합니다.
* **코드 구조:**
  ```python
  score = 0
  for i in range(size):
      for j in range(size):
          score += pattern[i][j] * filt[i][j]
  ```
* 외부 라이브러리 없이 순수 2중 반복문으로 구성되어 총 N^2회의 곱셈 및 덧셈을 수행합니다.

### 3) 부동소수점 오차 보정 및 동점 처리 정책 (`decide`, epsilon = 1e-9)
* **문제 배경:** 컴퓨터의 2진 부동소수점(IEEE 754) 연산 특성상, 수학적으로 같은 값이라도 미세한 오차(예: `0.9000000000000001`)가 발생해 잘못된 승자가 판정될 위험이 있습니다.
* **동점 처리 정책:**
  * 두 필터의 점수 차이 절대값이 허용 오차 epsilon(1e-9) 미만(`abs(score_cross - score_x) < 1e-9`)이면 **`"UNDECIDED"`(동점/판정 불가)**로 처리합니다.
  * **모드 1:** "판정 불가" 상태 정보로 사용자에게 출력합니다.
  * **모드 2:** 모델이 어느 한쪽으로 명확한 분류를 내리지 못한 것이므로, `is_pass()`에서 즉시 `False`를 반환하여 엄격하게 **`FAIL`**로 집계합니다.

### 3) FAIL 케이스 원인 분석

모드 2에서 실패한 3건(`size_5_1`, `size_13_2`, `size_25_1`)의 원인은 코드의 런타임 오류가 아니라 **입력 데이터의 대칭적 특성으로 인한 동점 발생**입니다.

1. **원인 상세:**
   * `data.json`의 필터는 단순 0/1 바이너리 필터가 아닌 중심 가중치(0.9)와 외곽 가중치(0.1)를 포함하는 실수형 필터입니다.
   * 실패한 패턴들은 Cross 필터의 활성 영역과 X 필터의 활성 영역에 동일한 대칭 가중치로 반응하여, 두 필터 간의 MAC 점수 차이가 0.0으로 계산되었습니다.
2. **처리 근거:**
   * 두 점수의 차이가 epsilon(1e-9) 미만이므로 `decide()`가 `"UNDECIDED"`를 반환했습니다.
   * 모드 2 자동 채점에서는 정답 클래스를 도출하지 못한 기권을 오분류로 간주하므로 정상적으로 `FAIL` 처리 및 사유(`동점(UNDECIDED)으로 판정 불가`)를 기록했습니다.

### 4) 성능 분석 표 해석 및 O(N^2) 복잡도 근거

I/O 오버헤드를 배제하고 순수 MAC 연산 구간을 각 크기별로 **10회 반복 측정한 평균 시간**은 다음과 같습니다.

| 크기 (N x N) | 연산 횟수 (N^2) | 실측 평균 시간 (ms) | 연산 횟수 증가율 (N^2) |
|:---:|:---:|:---:|:---:|
| 3x3   | 9   | 약 0.0009 ms | 기준 (1.0배) |
| 5x5   | 25  | 약 0.0016 ms | 약 2.78배 |
| 13x13 | 169 | 약 0.0098 ms | 약 18.78배 |
| 25x25 | 625 | 약 0.0266 ms | 약 69.44배 |

#### O(N^2) 복잡도 
1. **코드 관점 (이론적 연산 횟수):**  
   `mac()` 함수는 N행 N열을 순회하는 2중 `for`문 구조입니다. 가로 N칸, 세로 N칸인 격자 판의 모든 칸(총 N^2개)을 빠짐없이 하나씩 곱하고 더하므로 연산 횟수는 정확히 **N^2회**가 되며, 시간 복잡도는 **O(N^2)**를 가집니다.
   
2. **실측 데이터와의 일치성:**  
   - 크기가 3x3(9회)에서 13x13(169회)으로 연산량이 **약 18.8배** 늘어날 때, 실측 시간도 0.0009ms에서 0.0098ms로 **약 10.9배** 증가했습니다.
   - 크기가 3x3(9회)에서 25x25(625회)로 연산량이 **약 69.4배** 늘어날 때, 실측 시간도 0.0009ms에서 0.0266ms로 **약 29.6배** 증가했습니다.
   - 이를 통해 행렬 크기가 커질 때 실행 시간이 면적(N^2)에 비례해 증가함을 확인할 수 있습니다.
